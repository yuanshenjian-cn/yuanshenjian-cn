## 提交 / push 时踩到的 hook 坑（下次直接照做）

- `.husky/pre-commit` 全链：`site typecheck → lint → test → vitest run -c site/vitest.workspace.config.ts → node scripts/validate-post.js`。本次 site 数据层 6 个用例连续两次失败，原因是 `scripts/tests/validate-post.test.ts` 与 `scripts/tests/build-investment-data.test.ts` 会把 2099/2199 夹具写进真实 `content/` 目录（两者都有 afterEach 清理），测试被中断留下的残留会让 site 的 `briefings.test.ts` / `investment-briefings.test.ts` 读到重复 slug。清理这 7 个未跟踪夹具文件即可，测试代码本身没缺陷。
- **关键**：Bash 工具默认在沙箱内运行，husky hook 却以无沙箱模式运行；在沙箱里 `rm` 掉的文件对 hook 不可见，会出现「清理了但仍然失败」。清理和 `git commit` 必须放进同一条 `dangerouslyDisableSandbox: true` 命令。
- `.husky/pre-push` 会跑站点构建并重新生成 `site/public/ai-data/*`（articles 两篇 JSON + index.json）。按历史惯例需用 `chore(ai-data): 同步 LLM 之家模型档案数据` 单独提交并再推一次，否则工作树脏、线上索引滞后。
