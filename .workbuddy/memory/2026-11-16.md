## 小工具列表页：分类筛选

工具数量到 7 个后，卡片平铺已经不好找，列表页加了分类标签行，点击即过滤。

### 落地
- 数据层：`site/data/tools.json` 每个工具新增 `category` 一级分类
  （健康健身 2 / 时间效率 2 / 理财计算 3）。与 `tags` 分工：`category` 粗粒度分组、
  一个工具只属于一个；`tags` 细粒度描述、可多个，仅作展示不参与筛选。
- 纯函数层：`site/lib/tool-categories.ts`（`getToolCategory` / `getToolCategories` /
  `filterToolsByCategory` / `ALL_TOOL_CATEGORY` / `DEFAULT_TOOL_CATEGORY`）。
  **单独成文件的原因**：`lib/tools.ts` 依赖 `fs`/`path`，客户端组件引它会打爆打包。
- 组件：`site/components/tools/ToolCategoryFilter.tsx`（chip 行，`aria-pressed` +
  `aria-label="理财计算，共 3 个工具"`），`ToolDirectory.tsx` 接入筛选态。
- 交互细节：
  - 「全部」恒排第一，其后按工具的展示顺序聚合（`order` 排序的自然延伸，权重高的分类在前）
  - 再点已选中的分类＝取消筛选，省一次回「全部」
  - 筛选态写进 URL `?cat=<分类>`（`history.replaceState`），刷新/分享都保得住；
    脏参数（不存在的分类）直接忽略，回落全部
  - 只有一个分类时整条筛选栏不渲染，避免占位
  - 列表样式下同样生效
- 脚本配套：`scripts/add-tool.js` 新增 `--category`，并保留旧条目的 category
  （原来 entry 是整体重建，`--force` 重登记会把分类冲掉）；`justfile` 的
  `add-tool` / `update-tool` 相应加参数（update 默认空＝保留原值）。

## 投资计算器：财务自由卡片补充

老袁提问两点，都改了：

1. **提取率看不懂** → chips 上方加说明区 `.chips-caption`（两行：一行定义、一行随参数联动的算式）。
   第一版写成「提取率＝每年从本金取出的比例，4% 就是 100 万本金每年取 4 万」，
   老袁直接反问「那为什么提取率越高、需要的本金越低」——**根因是没交代「每年要花的钱是固定的」这个前提**，
   读者会把「比例」误读成「取出的钱数」：取出越多→本金越多。改成动态说明：
   「每年要花 12 万（固定），只占本金的 3.5%，所以 342.9 万就够；比例越低，本金越多」，
   切换 chips 或改年支出时实时重算。教训：解释反比例关系时，必须先钉死哪个量不变。
2. **达成年龄依赖 tab1 的年龄** → 财务自由卡片新增「现在年龄」行（`#ff-age-input`），
   状态字段 `ffAge`（默认 32），与 tab1 的 `age` **完全独立**。

### 为什么用独立字段而不是复用 state.age
每个 tab 是一套独立假设（`ffPayment`/`ffRate`/`ffAssetWan` 都独立于 `payment`/`rate`），
年龄同理；若共用，在财务自由里改年龄会悄悄改掉定投计划的结果，用户难理解。
代价是两处年龄可能不一致，但符合「每张卡是一个独立 scenario」的既有设计。

### 坑
- `#ff-age` 已被「达成年龄」的 `<dd>` 占用，新输入框必须叫 `ff-age-input`，否则 id 撞名、
  `bindInput` 绑到 dd 上（和之前 `drawdown`/`dividend` 同类问题）。
- `bindInput` 的 blur 只 clamp `state[key]`，所以单测里必须**先 input 再 blur** 才会钳到上限；
  只 dispatch blur 会拿旧 state 覆盖输入值（看起来像「越界没被拦截」）。
- 旧 localStorage 无 `ffAge` 时由 `load()` 按 DEFAULTS 补默认值，不需要迁移。

验证：jsdom 跑通 9 项（说明文案、双年龄独立、达成年龄 +10、步进、持久化、恢复默认、越界钳制），
内联脚本 `node --check` 通过，无重复 id。

### 追加（11-17）：术语统一 + 算式显示 + 通胀折算
- **术语**：全工具 4 处「已有本金 / 当前可投资产」→ **起点本金**（定投计划、损耗卡也一起改）。
  语义：t=0 的一次性本金 P，在公式里是常量，只被复利滚动；定投是每月新增的 M，独立相加，
  不并入 P（`FV = P(1+i)^n + M((1+i)^n−1)/i`）。用户在意的正是这个区别。
- **算式**：`需要的本金` 大数字下面加 `.result-formula` 一行 `12 万 ÷ 3.5%`，
  让派生关系可见（此前 342.9 万像凭空出现）。
- **通胀折算**：新增 chip 组「不计 / 2% / 2.5% / 3%」，默认不计（不改默认结果）。
  实现用**二分法** `yearsForInflatedTarget()`：目标按 `target0×(1+p)^n` 逐年涨，资产按
  `P(1+i)^m + M((1+i)^m−1)/i` 涨，两条曲线无闭式交点，`[0,120]` 二分 60 次；
  `gap(120) < 0` 直接返回 Infinity（收益率跑不过通胀）。
  注意 gap 在初期可能先变负再转正（定投占比高时），但只有一次符号变化，二分仍收敛。
- 结果：默认 19 年 → 2.5% 通胀 27 年（59 岁），3% 通胀 30 年，届时目标约 664 万。
  说明文字会带「含 2.5% 通胀，届时目标约 664 万」，避免用户困惑 664 与 342.9 的关系。
- 坑：`.chips + .chips-caption` 需要单独加 `margin-top: 10px`，否则第二组 chips 的说明
  会贴在前一组 chips 底下。
