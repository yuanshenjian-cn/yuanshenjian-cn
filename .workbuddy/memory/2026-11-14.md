# 2026-11-14

## 博客新增「小工具」板块（/tools）

目标：把独立 HTML 单页小工具（首个为番茄钟）集成进博客，方便后续持续新增。

### 落地方案
- 注册表唯一真相源：`site/data/tools.json`（slug/title/description/emoji/tags/addedAt/featured）
- 读取层：`site/lib/tools.ts`（校验 slug、去重、置顶+日期排序、embed 路径、冲突检测）
- 工具本体：`site/public/tools/<slug>/view.html`（不进 React 渲染，静态托管）
- 列表页：`site/app/tools/page.tsx` + `site/components/tools/ToolDirectory.tsx`（客户端组件，卡片/列表双视图，偏好存 localStorage `ysj-tools-view-mode`）
- 详情页：`site/app/tools/[slug]/page.tsx`，整屏 iframe 承载工具，顶部条含「工具列表 / 新窗口打开」
- Header 导航新增「工具」（wrench 图标）；sitemap 纳入 `/tools` 与各工具页
- `site/components/layout/FooterGate.tsx`：`/tools/<slug>` 下隐藏页脚，避免 iframe 外多余滚动
- 一键新增：`just add-tool <html> <slug> <标题> <说明> [emoji] [tags]` → `scripts/add-tool.js`
- 测试：`site/tests/lib/tools.test.ts`（元信息完整、slug 唯一、view.html 存在、index.html 冲突守护）

### 关键坑
- 静态导出下 `/tools/<slug>` 会产出 `dist/tools/<slug>.html`；工具入口若用 `index.html` 会与
  详情页路由争夺同名产物，构建后页面变裸 HTML。**入口文件固定命名 `view.html`**，并有测试守护。

### 环境注意
- 本机 `next build` 在 agent shell 里会被注入的 NODE_OPTIONS 语言 shim 打断
  （node-brokered-fs-shim 报 `No such file or directory`）；需 `NODE_OPTIONS="" npm run build` 才能正常构建。
- `next build` 会覆盖 `site/dist`，导致正在运行的 `next dev` 变 500/404，构建后需重启 dev server。
